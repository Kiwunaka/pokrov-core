# Core runtime contracts

POKROV Core parses managed profiles and runs the embedded sing-box engine in the client. The [repository map](../README.md#layout) names the owning modules. The App owns account sessions, signed catalog verification, transport choice and host permissions. The [build manifest](../config/release.json) pins the source dependencies. The client manifest and the capabilities read from the loaded library determine what a particular binary supports.

## Profile and transport admission

- Native profiles are sing-box JSON. The parser normalizes supported legacy DNS forms before strict decoding, preserves interface bindings and detours, rewrites the legacy DNS route target to `hijack-dns`, and removes Portal's top-level `_meta`. Unsupported legacy references and per-server overrides fail closed. Profile parsing errors never include the profile. Native Xray JSON is rejected.
- The `pokrov_client` build retains TUN and authenticated local SOCKS, HTTP and mixed inbounds. Remote server inbounds and server-only transports are omitted. The managed XHTTP, AWG, HY2, DNS and WARP paths stay in the embedded engine. Protocol support is read from the loaded Core descriptor and intersected with the host's usable adapters.
- AWG2 and AWG 3.1 have distinct managed contracts. AWG 3.1 requires its explicit contract ID. The default-off managed HY2 path requires an approved managed profile. Raw HY2 URI conversion is disabled. The capability schemas are listed in the [repository map](../README.md#layout).
- DNSTT and MTS are TCP VLESS detours with a pinned server Noise key. MTS carries KCP and smux over the board. Its separate API bootstrap runs an owned loopback proxy that closes independently of the main VPN. VK carries TCP streams through TURN, DTLS, KCP and smux; it requires inner VLESS REALITY/TLS authentication. Android verifies VK challenges through its foreground WebView and answers the same pending CommandServer or isolated probe in memory. Cancellation closes that request; late answers cannot complete another connection. Slipstream is an optional TCP carrier. The trusted host supplies the installed Slipstream executable path, and the profile supplies the resolver, domain and leaf certificate. Core owns the child, uses private stdin for control and releases the child and its sockets on close or interface reset.
- WARP supports WireGuard and MASQUE over HTTP/2. MASQUE registers a separate local device, pins the peer key returned by the registration API and carries IP packets through the existing userspace stack. Psiphon provides a TCP detour before the authenticated POKROV server; its bootstrap connections follow the configured detour and interface binding. Credentials and registration payloads stay on the device. Runtime proof comes from the selected outbound's egress.

## Host lifecycle

The Android binding exposes libbox and its command server. The host provides the VPN interface, protected/bound sockets and device certificate trust. Android attaches stage/start, stop and results to the selected profile and service generation. A stale callback cannot complete a later operation.

On Windows the privileged host owns network state and binds Core to the captured physical interface. The auto-route TUN interface is named `POKROV`, which lets the host restore Core-owned addresses, routes and DNS after stop or failure. The desktop exports, ABI version and required capabilities are in [abi-contract.json](../config/abi-contract.json). Callers release owned C strings with `freeString`. Stop and cancellation settle against the corresponding operation identity.

`StartedService.CloseService` stops the current engine and keeps the command server's observers available for another start. `StartedService.Close` is terminal and releases the observers and URL-test history. Linux has a separate [private daemon contract](../platform/linux/README.md). Apple is built through its static binding and exposes its own loaded capability inventory.

## Signed routing and Smart Access

- Catalog DNS and route rules can carry a `pokrov_catalog_window` on supported top-level exact/suffix domain matches. Core validates the issue/expiry window and stops matching at expiry using a monotonic deadline. The App verifies signatures and revision floors, selects the rules and supplies their untimed continuation. Catalog DNS failure can use the explicit `bypass_if_failed` path. This path cannot be combined with DNS response/evaluate/race actions.
- The `pokrov-smart-access` outbound takes the host-verified grant projection for the active account, device and profile. It enforces domain scope, bounded literal relay targets, deadlines and admission limits. It accepts visible-SNI TLS over TCP/443. ECH is denied unless an approved external relay is explicitly bound to the exact outer-SNI domain. Core uses the selected relay policy and does not make provider or signature decisions.
- Core isolates the expiration of new flows from termination of active flows. Renewal and restriction apply to the matching live lease instance. Revocation stops the affected flows without creating broader route access. Native enforcement is scoped to the active runtime and bound settings. The App owns durable policy floors and reconciles runtime state across a UI restart.
- Transport proposals, budgets and signed bindings originate in the host. Core exposes the loaded transport inventory and the bound startup, proof, restriction and stop operations. An unverified or stale profile or runtime binding cannot be substituted for the operation the host admitted.

## Connectivity proof and diagnostics

An isolated candidate probe has its own Core instance, captured network binding, deadline and cancellation. It does not install host routes, listen for traffic or update the persistent cache. It requests the owned HTTPS egress marker followed by the required body over the protected outbound. A second owned target may be tried within the same deadline. A successful TCP connection or TLS handshake alone does not establish usable egress.

Runtime endpoint probes and selector-group probes capture the current instance and selected proxy leaf. Direct, block, DNS and unsupported or cyclic groups cannot provide egress proof. A result from a different generation or selected leaf is discarded. The URL-test cache is diagnostic data and cannot complete an egress probe.

Failed probes expose closed operation and cause fields, the observed OS error or HTTP status when present and stage timing. When both owned targets fail, the reserve's verdict includes the primary target's bounded diagnostic. Addresses, response bodies, profile material and raw command errors stay local. The public event envelope is defined by [core-event-abi.json](../config/core-event-abi.json).
